# uitest — стенд тестов на mock-клиенте

Прогоняет настоящий код аддона без WoW: Lua 5.1 через `fengari`, WoW API заменён
заглушкой `mock.lua`. Ловит `nil`-глобалы, опечатки в методах, ошибки вызовов, регрессии
логики, «запрещённые» события (боевой лог), неверные цвета.

## Установка и запуск

```bash
cd templates/uitest
npm install                      # fengari + luaparse (один раз)
node check.js ../starter         # синтаксис всех .lua (luaparse, 5.1)
node run.js ../starter           # smoke-тест на mock-клиенте
npm test                         # оба шага подряд
```

Успех: `ИТОГ: все проверки пройдены`, код выхода 0. Любой `FAIL`/`LUA ERROR` — код 1.

## Как подключить свой аддон

* `run.js`/`check.js` принимают путь к папке аддона (по умолчанию `../starter`).
* `test_smoke.lua` содержит `FILES_ORDER` — порядок файлов **как в TOC**. Добавили файл —
  добавьте его в список, иначе тест загрузит аддон неполным.
* Заглушки клиентских API дописываются в `mock.lua` по мере надобности: `C_Item`,
  `C_Map`, `C_Container`, `C_MountJournal`, `C_TransmogCollection` и т.д.

## Что уже проверяется

загрузка и дефолты, приветствие в чат, отказ от боевого лога, окно (тумблер, заголовок),
добавление/вычёт попыток, строки списка и футер, вкладки, слэш-команды, словарь и
переключение языка (включая скрытие японского на enUS-клиенте), кнопка миникарты,
добыча из строки `CHAT_MSG_LOOT`.

## Грабли стенда

* Файлы аддона грузятся с `env = MOCK` — в этом окружении нужны `table`, `string`,
  `pairs`, `UIParent`, `SlashCmdList` и прочее. `mock.lua` копирует все глобалы в `MOCK`
  в конце; если добавляете новый глобал, создавайте его до этого места.
* Новый фрейм в заглушке **скрыт** (`__shown = false`), как в игре.
* `GetBuildInfo()` возвращает `version, build, date, tocversion` — 4-й аргумент это TOC.
* Глобал `L()` аддона живёт в `MOCK`: в тесте `local L = MOCK.L` после загрузки.
* Заглушка не рисует: визуальные наезды проверяются в игре или HTML-макетами.
