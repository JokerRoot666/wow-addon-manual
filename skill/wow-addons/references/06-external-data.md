# 06. Внешние данные: Wowhead, DB2 (wago.tools), обход блокировок

Аддон в сеть не ходит. Всё внешнее превращается в **сгенерированные Lua-файлы** скриптами
на машине разработчика: шансы, луты, модели, названия. В игре — только чтение таблиц.

Схема:

```
wago.tools ──db2_fetch.py──> build/wow/*.csv ──gen_builtin.py──> DataBuiltin.lua
                                     └────────gen_loot.py──> DataLoot.lua
Wowhead tooltip ──build_info.py──> DataInfo.lua (шанс + источник + зона)
Wowhead страницы ──wowhead_chances.py──> кэш ──merge_chances.py──> DataWowhead.lua
SavedVariables (снимок из игры) ──mog_chances.py──> DataMogWowhead.lua
```

Правило: `Data*.lua` **руками не править** — следующий запуск генератора перезапишет.
Кэш ответов обязателен: повторный запуск не должен ходить в сеть (иначе 20 000 предметов ×
два источника = часы и бан).

## Wowhead: два разных источника

### 1. Tooltip-API (быстро, машиночитаемо)

```
https://nether.wowhead.com/tooltip/item/<itemID>?dataEnv=1&locale=0   # enUS
https://nether.wowhead.com/tooltip/item/<itemID>?dataEnv=1&locale=7   # ruRU
```

Отдаёт готовый HTML тултипа + служебные поля (источник, зона, качество). Этим пользуется
`tools/build_info.py`: для каждого предмета берёт шанс, имя источника и зону; отдельным
запросом с `locale=7` — русские названия зон (они совпадают с картами клиента, поэтому
континент потом ищется цепочкой `C_Map.GetMapInfo` прямо в игре).

Плюсы: не парсится вёрстка страницы, стабильно, быстро. Минус: шанс дропа в тултипе есть
не всегда — для полной картины нужна страница предмета.

### 2. Страница предмета/NPC/зоны (медленно, под WAF)

Шансы и «Dropped by» лежат в HTML как данные Listview:

```js
new Listview({id: 'drops', data: [{id: 50818, count: 3, outof: 400, ...}]})
```

Процент = `count / outof * 100`. У NPC страница (`/ru/npc=<id>`) отдаёт список дропа тем
же Listview; у зон (`/ru/zone=<id>`) — «ловится в» с шансом за заброс (используется для
рыбалки по зонам).

**Что мешает:** Cloudflare/Amazon WAF. После нескольких десятков запросов приходит
`202`/`403`/страница «Let's confirm you are human». Это не ошибка скрипта, а лимит.
Лечение: пауза 10–30 минут, смена темпа/прокси, **прохождение проверки человеком** в
браузере. Обходить капчу автоматически нельзя — правило проекта и здравый смысл.

### 3. Сбор через уже открытый браузер (обход WAF без обхода капчи)

Рабочий приём: страницу нельзя скачать `curl`/`requests`, но можно получить из вкладки,
где человек уже сидит на wowhead (куки, пройденная проверка):

1. Локальный приёмник (только `127.0.0.1`):
   ```bash
   python tools/recv.py       # http://127.0.0.1:8123
   ```
   `GET /pending` — какие ID ещё не собраны, `GET /rares_ids` — список с именами,
   `POST /save/<имя>` — сохранить часть в `tools/build/inbox/`.
2. В консоли браузера — JS, который для каждого ID делает
   `fetch('/ru/npc=' + id, {credentials:'include'})` (тот же origin, куки на месте),
   вырезает `new Listview({id:'drops', ...})`, считает проценты и отправляет части
   по 12 мобов POST-ом на `127.0.0.1:8123/save/loot_rares3_<время>.json`.
3. Слияние: `python tools/loot_rares.py` → `python tools/gen_loot.py`.

Формат части: `{"<npcID>": {"n": "Имя", "c": класс, "d": [[itemID, процент], ...]}}`.
Важно различать `d: null` («страница не прочитана») и `d: []` («прочитана, лута нет»).

Тот же трюк с `https://r.jina.ai/` (текстовый прокси) используют для страниц зон, когда
WAF режет прямые запросы: `fish_scrape.py` сначала пробует `JINA + url`, затем прямой URL.

## DB2 из wago.tools

```
https://wago.tools/db2/<Таблица>/csv?build=<BUILD_ID>
```

`BUILD_ID` — конкретная сборка (`12.1.7.71087`); список сборок виден на
`https://wago.tools/db2/Item`. Локализованные таблицы — суффикс локали:
`ItemSparse_ruRU`, `Mount_ruRU`, `BattlePetSpecies_ruRU`.

Нужные таблицы (проверенный набор для аддона-коллекционера):

| Таблица | Зачем |
|---|---|
| `Item`, `ItemSparse_ruRU` | класс/подкласс/качество/имя, `ExpansionID` |
| `ItemEffect`, `ItemXItemEffect` | связь предмет → заклинание (`ItemXItemEffect.ID` ≠ itemID!) |
| `Mount_ruRU`, `BattlePetSpecies_ruRU` | `mountID`, `speciesID` — точная сверка с журналами |
| `JournalEncounter`, `JournalEncounterItem` | лут боссов журнала |
| `DungeonEncounter` | `encounterID` — ключ события `BOSS_KILL` |
| `JournalInstance`, `JournalTier` | инстанс → дополнение |
| `MapDifficulty`, `Difficulty` | тип сложности: рейд/подземелье |
| `Creature`, `CreatureDisplayInfo`, `CreatureDisplayInfoExtra` | рарники, классификация, displayID рас |
| `ChrRaces` | расы (id, муж/жен модели) |
| `Map` | карты/зоны |

Грабли скачивания (из реальной практики):

* **chunked-ответ.** Если CSV начинается с `1f24`/`a3f` — сервер отдал
  `Transfer-Encoding: chunked`, а скрипт записал длину чанка в файл. Лечение:
  скачивать через SSH-форвард с разбором chunked (`--via ssh`) и `--force`.
* **прокси рвёт длинные ответы** (`SSL error 35`, пустой ответ) — поднять форвард:
  `ssh -N -L 18081:wago.tools:443 root@<сервер>` и качать через него.
* **`mountID`/`speciesID` = 0 у всех** — не скачан `ItemXItemEffect` или связь ищется не
  через `ItemEffect.SpellID` (у эффекта `ID` — это ID эффекта, не предмета). Это уже
  случалось: все связи обнулились.
* **база вдвое меньше** — нет `ItemSparse_ruRU` (имена берутся из урезанного
  `ItemSearchName_ruRU`).
* **меньше боссов** — не скачаны `JournalEncounter*`/`DungeonEncounter`.

Проверки после сборки: число записей (`grep -c '^    \[' DataBuiltin.lua`), доля связанных
(`BuiltinLinked.mount/species`), несколько известных предметов вручную.

## Генерация Lua-таблиц: формат

```lua
-- DataLoot.lua (фрагмент)
ns.LootBuild = "12.1.7.71087"
ns.LootBoss = {
    [227] = { "Инквизитор Гершан", 63, "2169,2170" },   -- encounterID -> имя, instanceID, "itemID,..."
    ["j1432"] = { "Босс без DungeonEncounter", 0, "" }, -- ключ-строка, если encounterID нет
}
ns.LootNpc = {
    [50338] = { "Кор'нас", 2, "81404,87217" },          -- npcID -> имя, classification, предметы
}
```

Приёмы, которые экономят размер и время:

* предметы — одной строкой `"1,2,3"`, разбор при первом обращении + кэш;
* имена дублируются редко; ID — числа;
* порядок записей стабильный (детерминированная пересборка, чистый diff);
* сгенерированный файл начинается с шапки «сгенерировано скриптом, не править»;
* `ns.<Имя>Build` — номер сборки данных, видно в интерфейсе и логах.

## Проверка данных перед встраиванием

* `lua_check.py` на сгенерированный файл (баланс блоков);
* `load()` файла на mock-клиенте — таблица вообще читается;
* счётчики записей и несколько «эталонных» значений (известный босс, известный предмет);
* пустые таблицы допустимы, но должны быть явно объяснены («страница прочитана, лута нет»).

## Правила гигиены

* Все внешние запросы — через прокси (`127.0.0.1:10808`) или SSH-форвард, не напрямую.
* Кэш — обязателен; ключ кэша = ID + локаль + версия эндпоинта.
* Не хранить в репозитории мегабайты сырых страниц, только сводный JSON/Lua.
* Капчу и WAF проходит человек; скрипт ждёт и продолжает.
* Не выдумывать данные: если источник пуст — в аддоне «—»/«?», а не «примерно 1%».
