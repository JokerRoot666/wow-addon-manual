# 07. Локализация, версии и релиз

## Схема локализации, которая масштабируется

**Русский текст — исходник.** В коде пишется `L("Список")`. Для `ru` функция возвращает
строку как есть (никуда не смотрит), для остальных — ищет перевод в
`Locale.dict[<язык>][<русская строка>]`. Непереведённая строка остаётся русской:
интерфейс никогда не показывает пустоту и не «светит» ключи.

```lua
-- Locale.lua
function L(s)
    local d = Locale.dict[Locale.current]
    if d then
        local t = d[s]
        if t then return t end
    end
    return s
end
ns.L = L
```

```lua
-- Locale_en.lua (сгенерирован; ключ = русская строка целиком)
local ADDON, ns = ...
local Locale = ns.Locale
if not Locale then return end
Locale.dict.en = {
    ["Играбельные"] = "Playable",
    ["Не играбельные"] = "Not playable",
    ["Попытки"] = "Tries",
}
```

Ключ — **вся строка, включая пробелы и пунктуацию**. Поэтому любая правка русского текста
= новый ключ; для этого есть генераторы (`wrap_locale.py`, `rekey.py`), которые
переносят старые переводы и выбрасывают сирот. Не «улучшайте» формулировки мимоходом.

## Языки и клиенты

| Код | Клиент | Замечание |
|---|---|---|
| `ru` | ruRU | исходник, словаря нет |
| `en` | enUS/enGB + все незнакомые | фолбэк |
| `de` | deDE | |
| `fr` | frFR | |
| `es` | esES, esMX | один словарь |
| `it` | itIT | |
| `pt` | ptBR, ptPT | один словарь |
| `pl` | plPL | |
| `ko` | koKR | только на корейском клиенте |
| `zh` | zhCN | только на упрощённом |
| `zhtw` | zhTW | только на традиционном |
| `ja` | jaJP | только на японском |

Азиатские языки нельзя показывать на русском/западном клиенте: в шрифте нет иероглифов —
вместо текста «квадратики». Поэтому `Locale.Supported(key)` сверяет `GetLocale()` с
`script`-полем языка:

```lua
function Locale.Supported(key)
    for _, l in ipairs(Locale.available) do
        if l.key == key then
            if not l.script then return true end
            return tostring(GetLocale()) == l.script
        end
    end
    return false
end
```

Выбор игрока хранится в БД (`db.ui.locale`); незнакомый код сводится к `en`, азиатский
код при смене клиента — к языку клиента. Кодирование латиницей (`/ma lang ru`), понимать
и `ruRU`, `zh-tw`, `german`.

Смена языка = **пересборка окна** (тексты уже вписаны в FontString): `Locale.Set` →
`Locale.OnChange` → `UI.Rebuild()` + пересоздать кнопку миникарты и страницу настроек.

## Тексты, которые не переводятся

* Названия языков — всегда на своём языке (`Deutsch`, `日本語`) — игрок ищет свой.
* Имена предметов/зон/классов — из клиента.
* Технические ключи команд (`/ma lang ru`).
* Названия палитр/компоновок: если переводить лень — показывать английские для всех
  не-ru языков (`Locale.PrefersEn()`), а не русские.

## Переменные в строках

`L("%s добавлен в список, шанс %s")` — форматирование после локализации:

```lua
ns.Print(L("%s добавлен в список, шанс %s"), name, ns.Pct(chance))
```

Тест словарей проверяет: число/порядок `%s`/`%d`/`%.2f` в переводе совпадает с русским
ключом, нет дублей ключей, набор ключей одинаков во всех словарях.

## Сборочные скрипты локализации

```bash
# в аддоне
python tools/wrap_locale.py        # обернуть новые русские литералы в L("...")
python tools/gen_locale_en.py      # собрать Locale_en.lua из tools/_en*.txt
# рядом (DropLedger-i18n/scripts)
python rekey.py                    # перенумеровать словари: новые строки, выбросить сирот
python gen_locale_xx.py            # собрать десять словарей в ../DropLedger-i18n/locale
```

Рабочий процесс: написал строку → сразу `L("...")` → запустил генератор → проверил
`test13`-подобный тест (состав, дубли, подстановки) → перевёл новые ключи порциями.

## Версии

* `## Version` в TOC — версия аддона, видна в списке и на сайтах.
* `ns.version` в коде — показывается в окне. **Держать синхронно с TOC** (типичный баг:
  TOC 1.13.6, а окно пишет 1.13.0).
* Версия данных (`ns.LootBuild`, `ns.BuiltinVersion`) — отдельно: номер сборки клиента и
  версия генератора.
* Схема сообщений: `1.13.6` (major.minor.patch), в README — блок «что изменилось»
  сверху, по версиям.

## Сборка архивов

Два архива — разное назначение:

| Архив | Что внутри | Куда |
|---|---|---|
| `<Аддон>.zip` (полный) | всё: аддон + `tools/` + `README.md` | себе, для работы |
| `<Аддон>-CurseForge.zip` | только файлы аддона: `.toc`, `.lua`, `.xml` | публикация |

Правила, которые проверяет сборщик (иначе публикация «не встаёт»):

1. Ровно **одна** корневая папка с именем аддона: `MyAddon/MyAddon.toc`.
   Не `MyAddon/MyAddon/...`, не «файлы в корне zip».
2. Никаких `tools/`, `tests/`, `node_modules/`, `README.md`, `.git`, `build/`.
3. Имя TOC = имя корневой папки.
4. Ошибка сборки — исключение, а не «собрали кривой архив».

Псевдокод сборщика:

```python
files = [p for p in walk(ADDON) if p.suffix in ('.lua', '.toc', '.xml') and 'tools' not in p.parts]
assert (ADDON / f'{ADDON.name}.toc').exists()
with ZipFile(out, 'w') as z:
    for p in files:
        z.write(p, arcname=f'{ADDON.name}/{p.relative_to(ADDON)}')
    names = z.namelist()
    assert all(n.startswith(ADDON.name + '/') for n in names)
    assert not any(n.startswith(ADDON.name + '/' + ADDON.name + '/') for n in names)
```

Выкладка в игру: копировать файлы (не папку целиком с tools) в
`E:/Games/World of Warcraft/_retail_/Interface/AddOns/MyAddon/` и `/reload`.
Полезно печатать число скопированных файлов и обновлённую версию — сразу видно, что
выложилось именно то, что собрано.

## Публикация

* **CurseForge** (`curseforge.com/wow/addons`) — загрузка zip через веб или API;
  в TOC полезны `## X-Curse-Project-ID` и нормальные Notes на локалях.
* **Wago** (`wago.io`) — то же, `## X-Wago-ID`.
* **WoWInterface** — zip с той же структурой.
* **GitHub** — релиз с zip; популярный путь автоматизации — BigWigs Packager
  (`BigWigsMods/packager`) в GitHub Actions: он сам собирает архив по TOC, ставит версию
  из git-тега и льёт на Curse/Wago. Если проект не на GitHub, достаточно своего `pack.py`.
* Обновление сайтов — руками или API; в любом случае один и тот же zip.

## Тестирование перед публикацией

1. `node check.js` — синтаксис всех `.lua` (luaparse, Lua 5.1).
2. `node run.js` — все тесты на mock-клиенте, 0 FAIL.
3. Чистая установка: папка в `_retail_` с нуля (без старой БД) — первый запуск, приветствие,
   автоскан.
4. Обновление поверх: старая БД с прошлой версии — миграция, настройки на месте.
5. `_ptr_` (если доступен) — новый клиент: `## Interface` под PTR, проверка закрытых API.
6. Скриншот окна на 3 языках + светлая палитра (читаемость).
7. Проверка `/reload` и выхода из игры: SavedVariables записались.
